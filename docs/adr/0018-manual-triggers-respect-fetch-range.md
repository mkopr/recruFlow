# Manual triggers respect fetch_range; force_refresh stays scoped to already-seen bypass only

ADR 0008 already established that "manual" is not one concept in this codebase (`/ingest/{source}`'s `force_refresh` vs `/scheduler/run/{source}`'s audited re-run), and that `force_refresh` only bypasses [ADR 0009](0009-justjoinit-incremental-pagination-strategy.md)'s already-seen pagination early-stop — it has no effect on any other filtering. `fetch_range` is a second filtering mechanism, read unconditionally from `source.config_json` inside each connector's `run_x_ingestion` regardless of trigger type.

We decided `fetch_range` applies identically to automatic and both manual trigger paths, with no bypass — including when `force_refresh=True`. `fetch_range` is a deliberate, user-configured scope ("only jobs from the last week"), not a pagination-performance shortcut like already-seen dedup; if a user wants everything, they switch the mode to `"all"` rather than relying on incidental "manual trigger" semantics. This keeps `force_refresh` and `fetch_range` as two independent knobs. The alternative — `force_refresh=True` also bypassing the date filter — would restore "manual = fetch everything" as a single mental model, but was rejected because it re-merges the two trigger-type concepts ADR 0008 deliberately kept apart, and would surprise a user who narrowed a connector's range on purpose only to have "Fetch now" ignore it.
